# Design Document: e-means (Rust crate)

**Author:** Scott Idler
**Date:** 2026-11-13
**Status:** Implemented
**Review Passes Completed:** 5/5

## Summary

`scottidler/e-means` is a Rust library crate that ports e-means: mini-batch k-means where each centroid is the ratio of two exponential moving averages (per-cluster sum and per-cluster count). The port follows the CPU reference `NumpyEmeans` in Faiss `contrib/e_means`, pinned at Faiss commit `d1d9789a` (2026-11-12). Where the paper (arXiv 2611.09501) and the code disagree, the code wins.

### Goals

- A library crate: `e-means` (lib name `e_means`), CPU, f32 data, safe API over flat row-major `&[f32]`.
- Same algorithm as `NumpyEmeans` at `d1d9789a`: recipe laws, cosine schedule, EMA update, revival, closing pass, spherical mode.

- Parity with Faiss proven by tests that run in `otto ci`: the reference's own unit fixtures ported, plus end-to-end fixtures exported from Faiss.
- Deterministic: same seed -> bitwise same result, for any thread count.

## Proposed Solution

### Overview

- One package, no workspace, edition 2024. Shape copied from `~/repos/scottidler/expand-tilde` (the only pure library crate I have).
- Data is `&[f32]`, row-major, length `n * d`. No matrix crate in the public API.
- A config builder (`EMeans`) resolves a `Recipe`, produces a `Trainer` (the state machine), which finalizes into a `Model`.
- The Python reference is a test-time oracle only. A `compat/` harness (precedent: `~/repos/scottidler/mermaid-rs/compat/`) exports fixtures from `faiss-cpu==1.16.0`; the fixtures are committed under `tests/fixtures/` so `otto ci` needs no Python.

Terms used below:

- Pass (epoch): one sweep over `rows_i` rows in a fresh seeded order. T = 2.5 means three passes: full, half, full.
- Logical batch: the B rows that feed one EMA update. The recipe sets B.
- Chunk: one `accumulate` call. A logical batch can arrive in several chunks; chunking never changes the result (design under "Reduction order", gate in Phase 8).
- Block: `BLOCK_ROWS` consecutive rows of a logical batch, counted from the batch start. The unit of parallel assignment.
- Mass (`usage`, N_j): the EMA of how many rows cluster j received.
- Revival: every 5th update, clusters whose mass fell below a threshold are re-seeded next to a heavy cluster (a split).
- Closing pass: the last pass. Its per-cluster sums and counts replace the EMA centroids at `finalize`.

Flow of one logical batch:

1. `accumulate(rows)`: validate the chunk (finite, fits the batch). On the first chunk of a batch, freeze a snapshot of the centroids. Assign complete blocks against that snapshot; carry a partial block to the next chunk. Add counts and sums in row order.
2. `update()`: refuse unless the batch is complete. Compute alpha from the 0-based step. Apply the EMA. Every 5th update, run revival. Increment the step.
3. `end_epoch()`: record objective, imbalance factor, split count.
4. `finalize(self)`: closing means from the last pass, return the `Model`.

### Data Model

Algorithm spec (every item verified against Faiss `d1d9789a`; `REF` = `contrib/e_means`):

Recipe (`recipe.rs`):

- `INIT_USAGE = 2^-16` (`REF/base.py:25`), `ALPHA_MIN_FACTOR = 0.1` (`:18`), `CHECK_UNUSED_EVERY = 5` (`:21`), `SPLIT_EPSILON = 1e-4` (`:28`), `UNUSED_THRESHOLD = 0.1` (`:31`), `NO_REVIVAL_MAX_D = 2` (`:38`), `AUTO_QUALITY_MAX_D = 16` (`:46`).
- `round_pow2(v)`: 1 if `v <= 1`; else `low = 2^floor(log2 v)`, `high = 2*low`; pick `low` if `v/low < high/v`, else `high` (`REF/base.py:67-73`).
- Batch law: `B = round_pow2(C_B * k^0.134749 * n^0.876473 * T^0.813344)`. `C_B` = 0.035134 (throughput) | 0.00439175 (quality) (`:54-57`).
- Caps differ on purpose (`:143-148`): throughput `min(B, round_pow2(n/2))`; quality `min(B, n // 2)`. Then both `max(1, min(B, n))`.
- A caller `batch_size` becomes `min(batch_size, n)` and skips the batch law but keeps the step law (`:150-152`).
- Step law: `alpha0 = clamp(0.8244 * k^-0.4617 * B^0.9003 * n^-0.4498 * T^-0.1057, 1e-4, 1.0)` with the resolved B (`:64`, `:76-86`).
- `BatchLaw::Auto` -> quality when `d <= 16`, else throughput (`:89-99`).
- Revival threshold default: 0.0 when `d <= 2`, else 0.1; a caller value overrides; negative is an error (`:102-109`).
- `epoch_rows(n, T)`: `whole = floor(T)`, `remainder = round_ties_even((T - whole) * n)`. `whole == 0` -> `[remainder]`. Else `[n] * (whole - 1) + [remainder if nonzero] + [n]` (`:156-166`). The fractional pass sits before the last full pass: T = 2.5, n = 31 -> `[31, 16, 31]`.
- `total_steps = sum(ceil(rows_i / B))`. Tail batches are kept.
- `scheduled_alpha(alpha0, step, total) = alpha0 * (0.1 + 0.9 * 0.5 * (1 + cos(pi * min(step, total) / max(1, total))))` (`:174-178`). Step is 0-based: step 0 uses exactly `alpha0`; the 0.1 floor is never reached.

State (`trainer.rs`):

| field | type | note |
|---|---|---|
| `usage` (N_j) | `Vec<f32>`, k | starts at `INIT_USAGE` |
| `centroids` (c_j) | `Vec<f32>`, k*d | EMA state; un-normalized in spherical mode |
| `snapshot` | `Vec<f32>`, k*d | frozen at the first chunk of each batch; unit-norm readout in spherical mode |
| `batch_counts` | `Vec<u64>`, k | |
| `batch_sums` | `Vec<f64>`, k*d | deviation D2 |
| `pass_counts` | `Vec<u64>`, k | every epoch |
| `pass_sums` | `Option<Vec<f64>>`, k*d | last epoch only; deviation D2 |
| `carry` | `Vec<f32>`, up to `BLOCK_ROWS * d` | rows of a partial block, waiting for the next chunk |
| `pass_labels` | `Option<Vec<u32>>` | last epoch only, in feed order |
| `kernel` | `Kernel::Direct | Kernel::Gemm` | fixed at `begin` |
| `poisoned` | `bool` | set only by `NonFiniteState` |
| `step`, `epoch`, `rows_seen` | `usize` | |
| `split_rng` | seeded stream | consumed only by revival events with `nsplit > 0` |

EMA update (`REF/e_means.py:456-505`), in this order:

1. Add batch counts to `pass_counts`; in the last epoch add batch sums to `pass_sums`.
2. `gamma = 1 - alpha`. The test `alpha == 1` runs on the f64 alpha (`REF/base.py:269`), before any rounding to f32. If false: multiply all k masses by `gamma`. If true: no decay; untouched clusters keep their mass.
3. For each touched cluster (`n_j > 0`): `mass = retained + alpha * n_j`, where `retained` is the decayed mass, or 0 when `alpha == 1`.
4. `weight = alpha * n_j / mass`; `c_j += weight * (s_j / n_j - c_j)`; if `weight == 1` exactly, `c_j = s_j / n_j`.
5. Untouched clusters keep their position.
6. `alpha` and `gamma = 1 - alpha` are computed in f64, then each is rounded to f32 once and applied to the f32 arrays (NumPy 2 promotion: a Python float times an f32 array stays f32). `usage`, `mass`, `weight`, and the centroid move are all f32. The threshold bit-pattern fixtures need this.
7. Per-cluster mean `s_j / n_j` is computed in f64 from the f64 sums, then rounded to f32 (deviation D2).

Revival (`REF/e_means.py:261-300`), after the EMA when `(step + 1) % 5 == 0`:

1. `threshold = f32(sum_f32(usage)) * f32(tau) / f32(k)`, in that order. `sum_f32` here is a sequential f32 sum (deviation D8). `dead = usage < threshold` (strict). `donors = !dead && usage > 0`. `nsplit = min(#dead, #donors)`. If 0: return, no RNG draw.
2. Draw k uniforms (one per cluster, donors or not), floor each at `f64::MIN_POSITIVE`.
3. Donor key = `f64(ln_f32(usage_j)) - ln(-ln(u_j))`: the log of the mass is taken in f32 and then widened; the Gumbel term is f64 (`REF/e_means.py:275-278`). Non-donors get `-inf`. Take the `nsplit` largest keys, largest first.
4. Targets = the first `nsplit` dead indices, ascending. Pair positionally.
5. `offset_i = 1e-4 * (+1, -1, +1, ...)` over coordinates. Donor = `c * (1 - offset)`, child = `c * (1 + offset)`.
6. If donor == child on every coordinate: child coordinate 0 moves one ULP toward +inf, or toward -inf if that overflows.
7. Donor and child each get `usage_source / 2`. The dead cluster's old mass is dropped (total mass is not conserved).
8. Children are computed into scratch first. If any coordinate is not finite (a source near `f32::MAX`), nothing is committed and `update` returns `Error::NonFiniteState`.

Closing (`REF/e_means.py:531-564`):

- For clusters with `pass_counts > 0`: `c_j = pass_sums_j / pass_counts_j`. Others keep their current position, including revived children.
- Labels are the ones captured during the last pass, against centroids that were still moving. They are not final-nearest labels. `Model::assign` gives final-nearest.

Spherical mode (`REF/e_means.py:217-241`, `:303-307`, `:512-529`; `REF/e_means_spherical.py:32-42`):

- `begin` normalizes the initial centroids.
- EMA state stays un-normalized. Assignment uses a unit-norm readout refreshed after each update.
- Assignment is max inner product. Batch objective = (sum over rows, in f64, of the f32 value `-2 * ip`) `+ 2 * rows` (`REF/e_means.py:303`, `:432-434`).
- Closing: per-cluster mean in f64, rounded to f32, then `normalize_into` in f32. Unassigned clusters keep their position, normalized.
- `normalize_into` prescales by the row's max-abs before the norm; a zero row stays zero.
- Input rows are not normalized or checked. That is the caller's job, as in the reference.

Edge cases and the ruling for each:

| case | ruling |
|---|---|
| `d == 0`, `k == 0`, `k > u32::MAX`, `batch_size == 0` | `Error::InvalidParameter` at `begin` / `train` |
| `x.len()` not a multiple of `d`; `init.len() != k * d` | `Error::DimensionMismatch` |
| `n < k` | `Error::TooFewRows` |
| `n == k` in `train` (no caller init) | init is the rows as given, no RNG draw (matches `REF/e_means.py:593-600`). `train_from` and `begin` always use the caller's init. |
| `epochs` not finite, `<= 0`, or so small that `epoch_rows` sums to 0 rows | `Error::InvalidParameter` |
| `alpha0` outside `(0, 1]`, `unused_threshold < 0` or NaN | `Error::InvalidParameter` |
| T < 1 | one fractional pass; closing means come from those rows only; unvisited rows have `None` labels |
| `alpha == 1` (large B) | no decay; touched clusters get `mass = n_j`; with B = n one step equals one Lloyd iteration |
| no donors, or no dead clusters | revival returns before drawing any random number |
| fewer distinct rows than k | not an error; duplicate centroids go dead, revival splits a donor, the ULP rule keeps donor != child |
| cluster empty in the closing pass | keeps its EMA position (normalized in spherical mode) |
| a chunk that crosses a batch boundary | `Error::BatchOverflow`; the caller cuts chunks at batch boundaries |
| NaN or inf in the init centroids | `Error::NonFiniteInput` at `begin`. (Distances cannot catch this: a NaN centroid only loses every comparison; init `[[0], [NaN]]` labels all rows 0.) |
| NaN or inf in a row | `Error::NonFiniteInput` from `accumulate`, found by a scan of the chunk before anything changes. O(rows * d), against O(rows * k * d) for assignment. |
| a split child overflows to inf | `Error::NonFiniteState`; the trainer is poisoned |
| zero row in spherical mode | inner product 0 with every centroid; label is the lowest index among the maxima |

Reduction order (what makes chunking and thread count invisible):

- Blocks are cut relative to the start of the logical batch: rows `[0, BLOCK_ROWS)`, `[BLOCK_ROWS, 2 * BLOCK_ROWS)`, and so on; the last block of a batch is short. `BLOCK_ROWS` is a named const.
- A chunk that ends inside a block leaves its tail rows in `carry`. The next chunk fills the block first. `update` cannot run until the batch is complete, so `carry` is always empty at `update`.
- Assignment runs one block at a time per thread (`rayon`), each block against the frozen snapshot. A block's labels and distances depend only on its rows and the snapshot, so they do not depend on how the rows arrived or how many threads ran.
- Counts, sums, and the objective are then added on one thread in row order: `sums[label_i] += row_i`, `objective += dist_i`. This is the reference's order (`np.add.at`, `REF/e_means.py:48-86`). Cost O(B * d), against O(B * k * d) for assignment.
- Result: one chunk, row-at-a-time chunks, and irregular chunks give bitwise equal state, for any thread count.

Kernel choice (one predicate, fixed at `begin`):

- `Kernel::Direct` when `B * d < BLAS_THRESHOLD`, else `Kernel::Gemm`. `BLAS_THRESHOLD = 128000`, the value of `faiss.cvar.distance_compute_blas_threshold` (observed 2026-11-13; `faiss/utils/distances.cpp:642,662,705` picks by `nx * d`).
- Keyed on the recipe's B, never on chunk size or thread count, so a run uses one kernel from start to finish. `Model` remembers the kernel; `Model::assign` uses the same one.
- Direct: squared L2 by difference, f32, ties to the lowest index.
- Gemm: `||x||^2 - 2 x.c + ||c||^2` with `matrixmultiply::sgemm`, negative results clamped to 0.
- Known limit of the Gemm kernel, shared with Faiss above the same threshold: cancellation on data with a large common offset. f32 x = 10000, centroids `[10002, 10001]`: direct distances `[4, 1]`, expansion `[0, 0]`, tie to index 0, the wrong centroid. Clamping does not fix it. The README says to center such data first.

Trainer error contract:

- Every error except `NonFiniteState` is found before anything changes. The trainer is unchanged and the caller can correct and continue.
- `NonFiniteState` sets `poisoned`. Every later call returns `Error::Poisoned`.
- `update()` before the batch is complete -> `BatchIncomplete`, recoverable.
- `end_epoch()` before the pass has all its rows, or called twice in a row -> `EpochIncomplete`, recoverable.
- `accumulate` or `update` after the last pass ended -> `ScheduleComplete`.
- `finalize(self)` before the last pass ended -> `EpochIncomplete`; the trainer is consumed either way.

Deliberate deviations from the reference (each one goes in the README):

| # | reference | this crate | why |
|---|---|---|---|
| D1 | NumPy MT19937 / PCG64 streams | own seeded stream | porting NumPy's legacy shuffle buys nothing; parity tests feed init and orders |
| D2 | batch sums f32 (f64 scratch above 2^24 rows, copied back to f32 before the update, `REF/e_means.py:402`, `:439`); pass sums always f32 (`:352`); pass counts f64 (`:350`) | batch and pass sums f64, counts `u64`, mean taken in f64 then rounded to f32 | one code path, tighter means. Measured in Faiss by forcing its f64 scratch path on 5 small fixtures: worst per-centroid `||dc|| / ||c||` 1.3e-7, labels identical |
| D3 | `n < k` dies with a NumPy `IndexError` | `Error::TooFewRows` before any work | fail loudly with the cause |
| D4 | NaN input dies with `ValueError: 'list' argument must have no negative elements` | `Error::NonFiniteInput` from an entry scan | same |
| D5 | labels `int64`, -1 for unvisited | `Vec<Option<u32>>` | `None` reads as "not visited" with no magic value to remember. (`u32::MAX` would also be unambiguous; this is a clarity choice.) |
| D6 | object guarded against a second run at runtime | `finalize(self)` consumes the trainer | the compiler enforces it |
| D7 | `faiss.knn` picks its kernel per call by `nx * d` of that call | one kernel per run, picked by `B * d` at `begin`; batch-relative blocks | results independent of chunking and thread count |
| D8 | revival threshold sums the masses with NumPy's pairwise f32 reduction | sequential f32 sum | no port of NumPy's reduction. They differ in the last bits for k > 8 (`[2^24, 1 x 15]`: NumPy 16777230, sequential 16777216); only a cluster within a few ULP of the threshold is affected |
| D9 | no check on `alpha0` range, `batch_size == 0`, batch or pass row counts, or external statistics | typed errors for each | fail loudly at the call that is wrong |
| D10 | spherical `assign` returns similarities | `Assignment.distances` holds `2 - 2 * ip` in spherical mode | one meaning for the field in both modes |

### API Design

```rust
use e_means::{EMeans, BatchLaw};

// in memory
let model = EMeans::new(d, k)      // d, k: usize
    .epochs(5.0)                   // default 5.0; fractional allowed
    .batch_law(BatchLaw::Auto)     // Auto | Throughput | Quality
    .seed(1234)                    // default 1234
    .train(&x)?;                   // x: &[f32], len n*d

model.centroids();                 // &[f32], k*d
model.labels();                    // Option<&[Option<u32>]>: last-pass labels in row order; None inside = row not visited
model.epoch_stats();               // &[EpochStats { objective, imbalance_factor, splits, rows }]
model.recipe();                    // &Recipe
let a = model.assign(&y)?;         // Assignment { labels: Vec<u32>, distances: Vec<f32> }: final-nearest

// caller-driven (out of core)
let mut t = EMeans::new(d, k).begin(n, &init)?;   // init: &[f32], len k*d
let b = t.batch_rows();                           // B
for rows_in_pass in t.recipe().epoch_rows.clone() {
    let mut fed = 0;
    while fed < rows_in_pass {
        let want = b.min(rows_in_pass - fed);     // the tail batch is short
        // the caller supplies `want` rows, in one or more chunks
        t.accumulate(chunk)?;                     // Error::BatchOverflow past `want`
        t.update()?;                              // Error::BatchIncomplete before `want`
        fed += want;
    }
    t.end_epoch()?;                               // Error::EpochIncomplete if rows are missing
}
let model = t.finalize()?;                        // consumes the trainer
```

Other builder knobs, all from the reference constructor (`REF/e_means.py:161-177`):

- `batch_size(usize)`, `alpha0(f64)`: override the laws.
- `unused_threshold(f32)`: 0 disables revival.
- `spherical(bool)`.
- `max_points_per_centroid(usize)`: `train` only. When `n > k * limit`, trains on a seeded subset of `k * limit` rows kept in row order; other rows get `None` labels (`REF/base.py:206-226`).
- `capture_labels(bool)`: default true; false skips the n-length label buffer.
- `train_from(&x, &init)`: caller-supplied initial centroids.
- `Trainer::update_with(BatchStats { sums: &[f64], counts: &[u64], objective: f64 })`: apply statistics computed elsewhere (`REF/base.py:249-255`). Checked: `sums.len() == k * d`, `counts.len() == k`, `sum(counts)` equals the rows the current batch expects, every value finite, no rows already accumulated for this batch.
- Labels on the caller-driven path: the trainer captures last-pass labels itself, in feed order (position within the last pass). `Model::labels()` returns them in that order, all `Some`. `train` knows its permutation and returns them in row order. There is no `accumulate_labeled`.
- `Assignment.distances`: squared L2 in Euclidean mode, `2 - 2 * ip` in spherical mode.

`Error` variants (thiserror): `DimensionMismatch`, `TooFewRows`, `InvalidParameter`, `NonFiniteInput`, `NonFiniteState`, `Poisoned`, `BatchIncomplete`, `BatchOverflow`, `EpochIncomplete`, `ScheduleComplete`, `InvalidStatistics`.

Logging: `log` crate only. `debug!` on entry to each public function and one `debug!` per epoch with the stats. No logger is installed by the library.

## Alternatives Considered

### Alternative 1: Depend on the `emeans` crate
- **Description:** `cargo add emeans`, no new repo.
- **Pros:** exists today; same algorithm; its README claims parity within 1e-4.
- **Cons:** 3 days old, one author, 24 downloads; the parity test is excluded from the published crate; `build.rs` with MKL and Accelerate link features; hand-written AVX-512 `unsafe`; `i64` labels with -1.
- **Why not chosen:** Scott asked to build his own. The source stays useful as prior art for the kernel.

### Alternative 2: Fork `emeans`
- **Description:** fork, strip the BLAS features and the Python bindings, add parity tests.
- **Pros:** less code to write.
- **Cons:** inherits `build.rs` with BLAS link features and 3 `unsafe` kernel paths (AVX-512, AVX2, `cblas_sgemm`); unit tests are one integration file, not the house `tests.rs` layout; every upstream change needs a merge.
- **Why not chosen:** the core is about 1,800 lines; the parity harness is the larger share of the work and has to be written either way.

### Alternative 3: Bind Faiss C++ through FFI
- **Description:** call Faiss from Rust.
- **Pros:** bit parity for free.
- **Cons:** e-means lives in `contrib` as Python, not in the C++ library; a C++ toolchain and BLAS at build time.
- **Why not chosen:** there is no C++ e-means to bind.

### Alternative 4: Port NumPy's RNG for bit parity of `train(seed)`
- **Description:** implement MT19937, NumPy legacy shuffle, 53-bit doubles, PCG64 `choice`.
- **Pros:** `train(seed)` matches Faiss row for row.
- **Cons:** still not bitwise equal, because assignment kernels differ on near-ties; a large surface that tests nothing about e-means.
- **Why not chosen:** feeding init and orders into the caller-driven API isolates the algorithm with no RNG port.

### Alternative 5: Workspace with lib crate + CLI shim now
- **Description:** the house CLI shape from day one.
- **Why not chosen:** no CLI was asked for. Parked under Non-Goals with its reopen condition.

## Addendum: roads not taken

- Centroid tolerance on large or oversplit fixtures. The first draft required centroids within rtol 1e-4 of Faiss on an n=100000 mixture. Faiss fails that against itself (2.7e-2) when only its assignment kernel changes, and fails it again at n=4000 with k=64 over 16 blobs (2.3e-2). Do not re-add it; those fixtures compare objective and label agreement.
- One kernel only (Gemm in the library, direct as a test oracle). Rejected in review: Gemm gives wrong labels under a common offset, and Faiss itself runs the direct kernel below `nx * d` = 128000.
- Parallel per-block partial sums merged in block order. Rejected in review: f64 sums still depend on where blocks fall, so chunking would leak into results. Sums are added on one thread in row order.
- Distance-based NaN detection. Rejected in review: it misses a NaN centroid.
- f32 batch sums for exact reference fidelity. Rejected for D2. Reopen only if a separated-fixture parity test fails its 1e-5 bound and the cause traces to the sum type.
- Hand-written SIMD scan (the `emeans` crate's AVX2/AVX-512 argmin). Not in this plan. Reopen if the Phase 9 bench shows the argmin scan, not the dot product, dominates.
- `rand`'s `SliceRandom::shuffle` for permutations. Rejected: its output for a seed can change between `rand` releases. The crate owns Fisher-Yates.

## Technical Considerations

### Dependencies

- Runtime: `thiserror`, `log`, `rayon` (Phase 8), `matrixmultiply` (Phase 9), `rand_chacha` + `rand_core` (Phase 4).
- Dev: `serde`, `serde_json` (fixtures), `criterion`, `env_logger`.
- Test-time only, outside `otto ci`: Python via `uv`, `faiss-cpu==1.16.0`.
- RNG: `ChaCha8Rng` supplies the bit stream and nothing else. The crate owns: seed expansion (u64 seed -> 32-byte key by four SplitMix64 outputs, little-endian; `rand_core`'s own `seed_from_u64` is documented as free to change), stream assignment (ChaCha stream id = pass index for permutations, three reserved ids: init `u64::MAX`, revival `u64::MAX - 1`, and the `max_points_per_centroid` subset `u64::MAX - 2`; the third was added in Phase 5 so a subset run draws exactly what `train` on those rows draws), bounded integers (Lemire's method with rejection), Fisher-Yates, and the 53-bit uniform. Golden vectors in the tests fail if any of it moves.

### Performance

- Per epoch: O(n * k * d), all in assignment. Update is O(B * d) plus an O(k) decay.
- Memory: centroids + snapshot (2 * k * d f32), batch sums and last-pass sums (2 * k * d f64), labels (8 bytes per row when captured).
- Reference timings on this machine (64 cores), 2026-11-13, for calibration only:
  - n=100000, d=32, k=256, T=5 (throughput law, B=8192): `NumpyEmeans` 0.41 s; `faiss.Kmeans` 25 iterations 0.44-0.53 s.
  - n=100000, d=8, k=256, T=5 (quality law, B=1024): `NumpyEmeans` 4.35 s; `faiss.Kmeans` 25 iterations 0.45 s. Held-out MSE 8.49 vs 8.66. The small quality batch means about 490 Python-level updates; the Rust port should not pay that overhead, and Phase 9 measures it.

### Security

- No network, no files, no secrets in the library.
- `unsafe`: one call site (`matrixmultiply::sgemm` takes raw pointers), wrapped in a safe function that asserts slice lengths first.
- `compat/` installs pinned PyPI wheels into a local venv; it never runs in CI.

### Testing Strategy

- Unit tests per module port the reference's own fixtures; each test names the Faiss file and line it came from.
- Parity tests consume committed fixtures.
- Quality test compares against an in-test Lloyd.
- Tests must bite: in Phases 3, 4, and 6 the implementer breaks one line (decay order, strict `<`, readout refresh) and confirms the named test fails, then restores it.
- `cargo mutants` via the `mutants` otto task and workflow.

### Rollout Plan

- Blast radius: none. New repo, no consumers.
- Ship order: Phases 0 -> 10 in order. Release once, at Phase 10, by `bump release`.
- Consumers add it by git tag.
